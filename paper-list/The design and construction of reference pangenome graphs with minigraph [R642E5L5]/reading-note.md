## 0. 重建知识边界与作者的思考路径

### 0.1 2020 年的局面

写这篇论文时，领域里并存着三件事：

**第一，数据过剩了。** PacBio CLR/HiFi 和 ONT 长读长把"组装出一个接近 GRCh38 质量的个人基因组"从项目级任务变成了常规操作。到 2019-2020 年，GenBank 里已有十几个高质量人类组装（CHM1、CHM13、AK1、NA19240 等）。同时 HPRC（Human Pangenome Reference Consortium，人类泛基因组参考联盟）刚启动，目标是给人类建一个泛基因组参考。Heng Li 在 DFCI/HMS 的实验室拿的 U01HG010961 就是这个联盟的资助（推断：从致谢致意 Benedict Paten 和 Erik Garrison、以及论文主题与 HPRC 使命完全吻合看，这篇论文实质上是给 HPRC 交的设计方案）。作者手里有：minimap2（当时最成熟的链式比对器，几万行代码）、dipcall（基于组装的变异检出流程）、SynDip 基准（CHM1+CHM13 合成二倍体真值集）。这三样都是他自己的。

**第二，线性参考的问题已经被量化了。** GRCh38 的主体序列是少数个体的单倍型马赛克。Huddleston 等人 2017 年估计每个个体携带数千个参考里没有的大变异。这些变异不仅"缺"，而且有害：短读比对到 GRCh38 时，在 SV 区域附近会产生错误比对，进而产出假变异——这正是"missing heritability"（Eichler 2010）的一个机制来源。问题不是没人知道线性参考有缺陷，而是没有人给出一个可操作的替代品。

**第三，替代品有四个方向，全都不成立。** 这是理解本文的关键，值得一个个看，因为作者对每条路的否决方式，恰好定义了他自己的路。

### 0.2 四条旧路，四堵墙

**路线一：全文索引（full-text index）。** 把 N 条基因组原样存进一个 BWT/r-index 类压缩结构（deBWT、prefix-free parsing），压缩掉个体间相同的冗余。这解决了"存"的问题：k-mer 查询、k-mer 谱都能做。但它解决不了"参考"的问题——索引里没有坐标，基因注释投不上去；把一个 read 比对回整个集合，会得到命中多个基因组的冗余结果，怎么消解没有人知道。一个查询结构，不是一个参考。这条路的失败是结构性的：它从头就没打算提供坐标系。

**路线二：压缩 de Bruijn 图（cDBG）及彩色变体。** Cortex（Iqbal 2012）、TwoPaCo、Bifrost、Rainbowfish 把基因组集合里相同的 k-mer 塌缩成一个 unitig，用"颜色"标记样本。塌缩是它的优点，也是它的死穴。塌缩后：unitig 的位置对线性基因组是一对多关系，染色体坐标彻底丢失，基因组特征（基因、调控元件、已知变异）无法映射到图上；更隐蔽的是，k-mer 级的拼接会拼出任何输入基因组都不存在的路径（"encodes sequences more than the input"）——图比数据大；再往深一层，同一个样本的序列可以多次穿过同一个顶点，orthology（同源关系）无从定义，而没有了 orthology，"变异"这个概念本身在图上就定义不了——因为一个变异必须回答"相对于谁的哪个位置"。deBGA、Pufferfish 给 unitig 挂位置标签想救坐标，但几百个人类基因组下 unitig 数爆炸、每个 unitig 挂几百个标签，能否扩展是未知数；GBWT 给出了紧凑的单倍型索引表示，但当时没有工具能从多个人类基因组实际构造出 cDBG+GBWT。这条路的失败也是结构性的：塌缩这个操作本身和坐标系不相容。

**路线三：线性 MSA 导出的图。** Dilthey 等人的 HLA 图很成功——在一个位点上做多序列比对，把比对柱转成图。但一条染色体进不了一个线性 MSA。结构重排会让"线性"这个前提直接失效。这条路是位点级的，不是基因组级的。

**路线四：VCF 路线。** 当时最主流：先用变异检出工具 call 出变异写进 VCF，再把 ALT 序列作为替代路径插进参考（vg、Graphtyper/Graphtyper2、Seven Bridges Graph、NovoGraph）。这条路有两个连环问题。第一个是表达力：VCF 的坐标模型只给 REF 位置编号——插入序列没有自己的坐标。一个长插入内部的 SNP、一个 SV 嵌套另一个 SV，在 VCF 里根本写不出来。所以 VCF 路线天然只能编码"简单变异"，长插入、嵌套事件出局。第二个是上游的脆弱性：建图依赖先 call 变异再合并。而 SV calling 恰恰是最不可靠的——不同工具报的断点不同，同一个长插入在不同样本里可能被报成不同位置、不同长度，合并后同一个生物学事件碎成多个"不同变异"。用最脆弱的输出去建基础设施，基础设施本身也跟着脆。注意一个细节：这条路的表达力上限是 VCF 的格式能力，不是任何算法的能力——所以它是结构性失败，调参救不回来。

**还有一堵所有人都撞上的暗墙：碱基级图比对。** 前四条路之外的第五个事实：就算你造出了图，把一条查询序列精确比对到图上（碱基级、仿射 gap）也是没解决的问题。POA（Lee 2002）和 PaSGAL 只支持 DAG（有向无环图）；vg 把环展开成 DAG 再比对，最坏情况指数时间，而且本文实测 vg v1.21.0 建索引 14.7 小时、比对 1.8 小时、输出零条比对（"we have not been able to make vg work with our data"）；GraphAligner 用编辑距离（不区分 gap 开闭），对长 INDEL 的建模是错的；Jain 等人 2020 年的仿射 gap 环图比对算法只有理论分析，没有实现。也就是说，当时全世界没有任何工具能把一条染色体长度的序列做碱基级图比对。"把每个基因组精确比对进图"这个最朴素的想法，直接撞在这堵墙上。

### 0.3 作者的推理链：从"参考到底是什么"出发

现在可以模拟作者的思考了。面对四堵墙，最容易犯的错误是"再造一个更快的 cDBG"或"给 VCF 打个补丁"。作者没有从工具出发，而是先回答了一个定义问题：**参考基因组最重要的性质是什么？**

答案是：**它是坐标系，不是序列。** 生物学的每个数字都挂在坐标上——"chr1:12345"、GFF 的基因区间、BED 的峰值、VCF 的 POS、GWAS 的位点，全部是线性参考坐标。参考可以换序列（GRCh37→GRCh38 换过），但坐标系统必须延续，否则几十年的注释和工具链全部作废。由此得到一个几乎所有 prior work 都没有认真对待的约束：**任何参考泛基因组图，必须保住线性参考的坐标系统，并且是可逆的**——图上每个位置能对应回线性坐标，图上任意一条路径能翻译成线性坐标的区间序列。

从这个约束出发，论文的每一步都顺理成章：

**第一步：把约束写进数据模型（rGFA）。** 要保住坐标，最直接的办法是要求图上每个节点（segment）恰好来自一个基因组的一个位置——记录它的来源序列名（SN）、在来源序列上的偏移（SO）、是否在参考骨干上（SR）。这就是 rGFA 的三个 tag，薄得近乎平凡。但这个"平凡"的要求有重量：它禁止塌缩——不同基因组区域不允许共用同一个节点（vg 模型允许）。作者明确论证这是 feature 而不是限制：一旦允许塌缩，一个节点对应多个位置，orthology 定义不了、变异定义不了、路径到稳定坐标的翻译变成解谜（要看相邻节点才能判断 s1 指的是 chr1:100-200 还是 chr1:500-600）。塌缩图的"一般性"买来的是歧义；rGFA 用一点存储冗余买来的是坐标的平凡性。这个 trade-off 是全文最重要的建模判断。

**第二步：把构造方式从"call-merge"换成"align-absorb"。** 有了模型，怎么把 20 条基因组装进图？VCF 路线的失败是因为它把建图绑定在变异 calling 上——一个分类问题（"这里发生了什么事件"），答案脆弱且受格式表达力限制。作者换了一个问题：不判断"这里是什么变异"，只判断"这段序列图里有没有"——一个检测问题。没有就吸收进来（加节点加边），有就穿过去。这是 POA（partial order alignment，Lee 2002）的老思想——逐条序列增量比对、把新序列里对不上的部分补进图——只是 POA 当年只做蛋白质、只支持 DAG。作者把它搬到基因组尺度，允许环。这一步把建图从"最脆弱的下游分析"变成"最可靠的比对"，是整条流水线成立的根基。

**第三步：用"只编码大变异"绕开碱基级图比对墙。** align-absorb 需要把每条组装比对到图上，而碱基级图比对无解。作者的解法是让问题消失：**图里只放 ≥100bp 的 SV，不放小变异**。这个 scoping 的妙处在于它让图的几何结构反过来适配比对器的能力——图里凡是在碱基水平相似的区域，都已经塌在骨干上了；凡是路径不同的地方，分歧都 ≥100bp，大到链式定位（chaining，只看 minimizer 锚点的共线性，不做碱基比对）就足以选对路径。小变异不进场还有独立理由：小变异本来就用线性工具分析得很好；把几百万个 SNP 做成几百万个短节点会让图爆炸、让比对变差（Forge 的结论）、让所有下游任务变慢。所以"图只管 SV"是分工，不是残缺。**图的内容和比对器的能力被设计成互相匹配——这是全文最深的设计，也是作者最没有明说的地方。**

**第四步：解决"全基因组查询"的工程问题。** minimap2 的 chaining 是给 reads 调的：最大 gap 5kb（G=5000）。全基因组组装到图需要跨过长插入——一个 10kb 插入会把两侧的锚点隔开 10kb，minimap2 的参数会直接断链，两侧锚点分属两条链，插入就永远检测不到（§3.3.1 有具体计算）。所以 G 提到 100kb，gap cost 重新标定；代价是 chaining 的 O(n²) DP 在长 gap 下没法用 minimap2 的老启发式加速（启发式在长片段重复区会错过最优、产出假变异），于是引入 RMQ（Range-Min-Query）做混合加速：小窗口内精确搜索，大窗口内用线性 gap cost 的近似，近似解只在严格更优时才被采纳。再往上，线性链不跨节点，所以拓扑问题放在第二层"图 chaining"里解决：把线性链当单元，在图上找游走把它们接起来，用"游走长度最接近查询距离"来选路——用距离消歧，代替碱基比对消歧。

**第五步：把"哪里分歧"变成一个纯局部的问题。** 构造循环里最后一环：链给了锚点对，锚点对之间的大空隙就是候选分歧区。给每个空隙打分（h_i，§3.4），用 Ruzzo-Tompa 线性时间算法找最大正和区间，再对每个候选区做**局部碱基比对**——注意，这里的碱基比对是查询序列对"链给出的线性路径"做的，是 pairwise 比对，不是图比对。图比对墙被第三次绕开：链先把图路径拉直成线性序列，比对就退化成老问题。保留标准：≥100bp 的 INDEL 或 ≥100bp 区域一致性 <80%。这两个阈值保证了吸收进来的都是真分歧，代价是漏掉小事件——和"图只管 SV"的分工一致。

### 0.4 底牌与把握分布

作者的底牌不是新算法——RMQ、Ruzzo-Tompa、POA 都是现成技术——而是**他手里恰好有一切拼图**：minimap2 代码库（种子和 chaining 直接改，比对器部分的开发风险极低）、dipcall 和 SynDip（自己的验证工具，别人没有）、HPRC 时代红利（十几条现成的高质量组装）。所以这个项目的技术风险是"改一个成熟比对器 + 写一个构造循环 + 设计一个薄格式"，而生态价值巨大。这篇论文的形式——设计文档加系统演示，不追求 SOTA 对比——就是这个判断的产物。它投 Genome Biology 而不是算法会议：审稿人要的是"可扩展、可用、生物学家能用"，这正是论文的实验设计（三小时成图、dipcall 互盲、blacklist 应用）在回应的。

措辞分布是作者把握程度的地图。"we propose"（模型、格式）是设计主张；"we demonstrate"（20 基因组 2.7 小时）是工程事实；"we believe"出现在两处——minigraph 和 dipcall 找到的 SV 集"相似"、VNTR 区的两个 NA12878 组装分歧"是局部 misassembly 而非体细胞突变"——都是没有真值可依的判断。而 Discussion 里那长长一段关于碱基级图比对现状的综述（POA、PaSGAL、vg、Antipov、GraphAligner、Jain 一个不落），读起来不像科普，像辩护词：这是审稿人必然打的地方（"你为什么不做碱基比对？"），作者提前把"不是我不想，是全世界都没解"的证据摆满。论文结尾的"Our work is still preliminary"是同一策略的退路。反过来说，作者对自己最有把握的是格式论证——rGFA 那一节写得干净利落，一个例子、三条规则、两个限制，十分钟能验证。

叙述顺序（模型→格式→比对器→构造→演示）是教学顺序，不是发现顺序。更可能的真实过程（推断，依据：minigraph 2020 年 3 月就挂在 GitHub 上，早于论文；rGFA 定义极薄而构造算法极厚）：先有"用 minimap2 把组装比进图、把没比上的部分加进去"的工程原型，SN/SO/SR 三个 tag 是边做边固化的，坐标系论证是事后提炼的。薄的部分是设计直觉，厚的部分是工程实践——这是工具论文的正常形态，读者不必把叙述顺序当历史顺序。

### 0.5 四个核心问题

**Problem：** 给定同一物种的多条参考质量组装，构造一个"参考泛基因组图"（reference pangenome graph）：(i) 每个图位置有锚定在线性参考上的稳定坐标，图上路径可翻译回线性坐标区间（坐标系可逆）；(ii) 图紧凑地编码参考里没有的 ≥100bp 结构变异；(iii) 构造在小时级完成、可扩展到几十上百条基因组。在 2020 年的知识边界上，缺口是明确的：稳定坐标的图模型不存在，不依赖碱基级图比对的构造方法不存在。

**Motivation：** 线性参考是单倍型马赛克，每人携带数千个大变异；这些变异不仅被漏检，还主动污染现有分析——本文的 blacklist 实验把这条量化了：短读 SNP calling 的假阳性里有 21% 落在 <1% 的 SV 区域。同时 HPRC 需要一个可落地的参考图方案。解决了这个问题，才谈得上：给 HLA/KIR 这类高变异区做注释、给 SV 一个跨研究一致的表示（SV 没有 SNP 那样的"chr1:12345"约定，各家断点各说各话，参考图给出了共同坐标系）、给短读流程提供 blacklist/decoy、给未来的图分型打地基。

**State of Research / Gap：** 四条旧路的结构性失败（§0.2）：全文索引（BWT 集合索引）无坐标、冗余命中无解；cDBG/彩色 cDBG（TwoPaCo、Bifrost、Rainbowfish、Pufferfish、GBWT）塌缩掉了坐标与 orthology、且拼出输入中不存在的路径；线性 MSA 图（Dilthey）位点级；VCF 路线（vg、Graphtyper2、Seven Bridges、NovoGraph）受 VCF 表达力限制（插入无内部坐标 → 嵌套 SV 不可表示）且依赖脆弱的 SV call-merge。第五堵墙：碱基级环图比对无实现（POA/PaSGAL 只做 DAG；vg 展开指数；GraphAligner 编辑距离无仿射 gap；Jain 2020 只有理论）。所以"为什么之前没人做"不是没人想过——比对式建图（POA 路线）早在 2002 年就有了——而是它依赖图比对，而图比对是墙。本文的增量在于：用"只编码 ≥100bp 分歧"把墙拆了——图的内容被设计成链式定位（不需要碱基比对）就够用的样子。

**Contribution：** 核心洞见一句话：**先决定参考图必须保住什么——线性坐标与 orthology——再让数据模型（rGFA 的一节点一来源）、比对器（链式定位、无碱基比对）、构造策略（align-absorb、只收大分歧）三者围绕这个约束互相咬合；把"把基因组精确比对进图"这个当时无解的问题，换成"检测并吸收图里没有的序列"这个已解的问题，代价是明确画出图的能力边界（只管 ≥100bp SV、跳过重复区），而这个边界恰好和线性工具的分工互补。**

归纳出的贡献（按推进边界的类型分）：
- **新模型（新理解）：** rGFA——第一个带稳定坐标系的参考图数据模型，"一节点一来源"规则换来坐标的平凡可逆与 orthology 的良定义；配套 GAF 比对格式。
- **新解决方案：** minigraph 比对器——第一个实际可用的染色体级序列到图定位器（种子 → 线性链 → 图链，混合 RMQ 加速，无碱基比对）；以及增量图构造算法——POA 思想的基因组尺度实现（primary chains → 分歧区检测 → 局部 pairwise 比对 → 增广），20 个单倍型 2.7 小时成图。
- **新经验事实：** blacklist 实验——SV 区域（<1% 基因组）承载 21% 的短读假阳性 SNP，首次定量证明"线性参考的有害效应"；以及人类图/大猿图的变异图谱（VNTR 多等位性、端粒富集、谱系插入缺失不对称）。

新意主要来自新理解和新解决方案的组合，不是新算法——所有算法部件（minimizer、chaining DP、RMQ、Ruzzo-Tompa、POA）都是现成的。这篇论文真正发明的是**设计**：格式约束、比对器能力、构造策略三者互为前提的闭环。

## 1. Abstract｜全篇压缩

### 1.1 Task

领域：基因组学基础设施。任务：把同物种的多条高质量组装整合成一个参考泛基因组图——保住线性参考坐标、编码参考缺失的 SV、并让生物学家实际可用。关键科学问题：**图的稳定坐标系**（没有它，图无法承担"参考"的职能）与**基因组尺度的构造可行性**（没有它，图只是演示）。

### 1.2 Technical challenge for previous methods

既有表示要么没有坐标（cDBG、全文索引），要么表达不了长插入（VCF 路线）；而"精确比对进图"所依赖的碱基级环图比对在 2020 年无实现。所以 challenge 是双重的：模型层缺稳定坐标，算法层缺可行的图比对。

### 1.3 Key insight / motivation

参考泛基因组图首先是一个坐标系，不是序列容器或变异数据库。守住"每个图节点恰好来自一个基因组位置"，坐标、orthology、注释投影全部变得平凡；再用"逐条比对、吸收分歧"代替"call 变异、合并变异"来建图，并把图的内容限制在 ≥100bp 的分歧上——这个限制让无碱基比对的链式定位恰好够用，把无解的图比对问题从流水线里整个拆掉。

### 1.4 Technical contributions

- **rGFA 数据模型 + GAF 格式：** 在 GFA 上加 SN/SO/SR 三个 tag 定义稳定坐标，一条"一节点一来源"规则禁止塌缩图。好处：坐标可逆、orthology 良定义、注释可投影、切分节点不破坏坐标。
- **minigraph 比对器：** minimap2 式种子 + 两级 chaining（段内线性链 → 图上图链），无碱基比对。好处：染色体长度查询可用；68,857 条模拟 reads 上索引 100 秒、比对 79 秒，位点错误率 1.7%（对照 GraphAligner 589/140 秒、4.6%）。
- **增量图构造算法：** 逐条组装比对进图，用锚点空隙打分 + Ruzzo-Tompa 定位分歧区，局部 pairwise 比对验证后增广成图。好处：20 个单倍型 2.7 小时成图，图含 37,332 个变异。
- **实证与资源：** 人类图、大猿图、gfatools、blacklist 生成器。好处：SV 区域以 <1% 的基因组承载 21% 的短读假阳性 SNP，给线性流程一个立即可用的衍生品。

### 1.5 Experiment

最有代表性的证据：GRCh38 + 20 人类单倍型，24 线程 2.7 小时，98.1GB 峰值内存，148,618 节点 / 214,995 边 / 37,332 变异气泡；与 dipcall 的 SV 集互盲率 2.7%/6.0%；模拟 PacBio reads（N50 15kb）上比对速度比 GraphAligner 快 1.8 倍、位点错误率 1.7% vs 4.6%；blacklist 实验：29.2Mb 区域（约 0.9% 基因组）包含 GATK 假阳性 SNP 的 21%，而真 SNP 不富集（0.7%）。结论适用范围：≥100bp、≤100kb 的 SV，且仅在非重复、非 paralogous 区域。

## 2. Introduction

### 2.1 Task and application

- 任务定义：输入 = 线性参考（GRCh38）+ N 条参考质量组装；输出 = 一个 bidirected 序列图，其中每条参考序列是一条骨干路径，每条非参考序列是一条或多条替代路径（等位基因），图必须携带稳定坐标。评价目标：坐标可逆性、SV 编码完整性（≥100bp）、构造的可扩展性（时间、内存）、下游可用性。
- 重要性：线性参考的单倍型偏倚导致大变异漏检与短读错配（本文量化见 §4.2 E5）；SV 关联表型但长期被检测工具忽视。参考泛基因组图是把"每个人携带的参考外序列"变成可注释、可比对、可分型的一等公民。
- 应用：高变异区注释（HLA/KIR）；SV 的跨研究一致表示与分型；blacklist/decoy 供线性流程使用；近缘物种比较基因组学。

### 2.2 Technical challenges for previous methods

#### Technical challenge 1 — 图的稳定坐标系

**Previous method：** cDBG 路线（Cortex、TwoPaCo、Bifrost）把相同 k-mer 塌缩成 unitig；vg 的 path 模型允许任意区域塌缩成共享节点。

**Failure cases / limitation：** cDBG 图上无法表达"chr1:12345"；基因注释投不上去；图会拼出任何输入基因组都不存在的路径。vg 模型中同一个节点可对应参考的多个位置：路径 s2→s1→s3 要翻译回坐标，必须检查 s2、s3 才能确定 s1 指哪个位置；当 s2、s3 本身也对应多位置时，翻译变成组合解谜。

**Technical reason：** 塌缩操作的本质是把"序列内容"作为一等公民、把"基因组位置"降级为标签。一个节点一旦聚合了多个位置，节点到坐标的映射就从函数变成关系，坐标不可逆。这是 cDBG 的定义性行为，不是参数问题——不塌缩它就不叫 cDBG。

**Research gap：** 需要一个数据模型，其节点定义自带位置信息，使坐标映射是平凡的、可逆的、且在图的变换（切分节点、增删节点）下稳定。这就是 rGFA 要填的洞。

#### Technical challenge 2 — 基因组尺度的图构造

**Previous method：** VCF 路线（vg、Graphtyper2、Seven Bridges、NovoGraph）——先 call 变异写 VCF，再把 ALT 插成替代路径。

**Failure cases / limitation：** VCF 只给 REF 位置编号：一个 10kb 插入内部的一个 SNP、一个 SV 嵌套另一个 SV，在 VCF 里无处安放坐标，写不出来。此外 SV call-merge 的断点不一致会把同一个长插入碎成多个"不同变异"。

**Technical reason：** 这是格式的表达力上限：VCF 的事件模型（POS + REF/ALT）假设变异是"参考位置上的一次替换"，长插入的内部结构超出模型的表达能力。且构造依赖上游分类（"这是什么变异"），而 SV 分类恰是最不可靠的环节——两个问题叠加，路线结构性地到不了"完整编码长 SV"。

**Research gap：** 需要一条不经过变异 calling 的构造路线——直接把组装序列比对进图、把图里没有的序列吸收进来（POA 式），并且它不能依赖当时不存在的碱基级环图比对。minigraph 的构造循环填这个洞。

### 2.3 Our pipeline：如何解决 challenge

**Key insight（§0.5 已述）：** 坐标优先的模型（rGFA）+ 比对吸收式构造 + 只编码 ≥100bp 分歧，三者互相咬合，把图比对墙从流水线里拆掉。

**Contribution 1 — rGFA/GAF（解决问题 1）。** 做法：SN/SO/SR 三 tag + 一节点一来源 + 禁塌缩。收益：坐标平凡可逆；图的切分变换不破坏坐标（split 之后两个子节点的 SO 不变，路径拼起来仍是同一区间）；GAF 让比对路径能直接用稳定坐标写出，注释投影、blacklist 生成都是坐标运算。验证：整个论文所有下游分析（变异注释、blacklist）都建立在稳定坐标上——构造本身是存在性证明。

**Contribution 2 — minigraph 比对器 + 增量构造（解决问题 2）。** 做法：minimizer 种子 → 段内线性 chaining（G=100kb、混合 RMQ 加速）→ 图上 chaining（≤16 条最短路游走、长度匹配选路）；构造时扫锚点空隙打分、Ruzzo-Tompa 找分歧区、局部 pairwise 比对验证、增广。收益：20 基因组 2.7 小时成图（vg 处理不了这些数据）；无碱基比对而位点准确率不低于有碱基比对的 GraphAligner。验证：§4.2 E1、E2。

**Contribution 3 — 实证与 blacklist（解决问题的重要性）。** 做法：人类图 + 大猿图 + blacklist 实验。收益：给"线性参考有害"第一个定量数字，并给出线性流程可以马上用的衍生品。验证：§4.2 E5。

### 2.4 Demos / applications

论文的 demo 是 Fig. 4 的一个多等位 VNTR 区域（IGV 截图）：同一位置聚集了多个不同长度的长插入，两个 NA12878 组装彼此都不一致。这个图说明两件事：图能把连先进组装都搞不定的复杂区域如实地编码出来；naive 的比对式 SV caller 会在这种区域报出十几个低频插入——那是对同一组相关事件的碎片化误读。minigraph 把这些事件对齐成一个多等位气泡，正是图相对"call-merge"的优势所在。

## 3. Method

### 3.1 Overview

**具体任务：**
- 输入：一条线性参考（GRCh38）+ N 条组装序列（FASTA）。
- 输出：rGFA 格式的 bidirected 序列图；每条组装对图的 GAF 比对。
- 目标：图编码 ≥100bp 的 SV（100bp–100kb），每条路径可翻译成稳定坐标区间；构造时间小时级。

**总体流程（模块依赖）：** 两条流水线，比对器（Fig. 2a）被构造流水线（Fig. 2b）当作子程序反复调用。

1. **比对器**（给定图 + 查询序列 → 图链）：段上采 minimizer → 哈希匹配出锚点 → 每个段内做线性 chaining（忽略拓扑）→ 线性链之间做图 chaining（沿图拓扑连接、≤16 条最短路、长度匹配选路）→ 输出图链（锚点序列）与 GAF。无碱基比对。
2. **构造**（给定 N 条组装 → 图）：以 GRCh38 为初始图；对每条组装：跑比对器 → 取 primary chains → 过滤出 orthogonal 区域（单一 primary chain 覆盖 ≥100kb 且不与另一条 ≥20kb 的 primary chain 相交）→ 对链内相邻锚点对打分 h_i（Eq. 3）→ Ruzzo-Tompa 找最大正和区间（候选分歧区）→ 对每个候选区做查询对链路径的局部 pairwise 比对 → 保留含 ≥100bp INDEL 或 ≥100bp 区域一致性 <80% 的区域 → 增广图（切分节点、加新节点与链接）→ 下一条组装。
3. **下游**（给定图 → 分析）：稳定坐标投影、变异气泡提取（gfatools）、RepeatMasker/SDUST/etrf 注释、blacklist 生成。

先讲模型与格式，再讲比对器，再讲构造——这是论文的顺序，也确实是理解依赖的顺序。

### 3.2 Module 1 — rGFA 数据模型与 GAF 格式

**Motivation：** 图需要坐标系。GFA（Graphical Fragment Assembly）本身只有节点（S 行）和边（L 行），没有位置概念。且段坐标（segId, offset）有两个毛病：与线性注释脱钩，且对图变换敏感——把一个段切成两段，所有下游坐标全变。参考图必须有一个"切分节点也不变"的坐标。

**做法：** rGFA 在 GFA 的 S 行上加三个 tag：
- **SN:Z:** 稳定序列名——该段序列来自哪条输入序列（如 chr1 或某条组装的 contig 名）；
- **SO:i:** 在该稳定序列上的偏移（0-based）；
- **SR:i:** rank——0 表示该节点（或边）在线性参考骨干上，>0 表示非参考。

稳定坐标就是 (SN, SO) 对，写作 "chr1:9" 这种线性坐标的推广。一条路径 S1 S2 S3 若三段分别来自 chr1:0-5、chr1:5-8、chr1:8-12，则路径对应 "chr1:0-5 chr1:5-8 chr1:8-12"，相邻且同序列的区间可合并成 "chr1:0-12"。若中间走的是插入段（如 Fig. 1 中来自另一条序列 foo 的段），路径写为 "chr1:0-8 foo:8-16"——两种坐标系混排，但每个位置都有唯一的名字。

一个容易看漏的点：**SO 是段在来源序列上的偏移，不是段间相对坐标**。所以把 S1 切成两段后，两个子段的 SO 不变，路径拼起来仍然读出 "chr1:0-12"。坐标稳定性来自"每个节点自己携带位置"，而不是来自"位置由邻接关系推导"。

**为什么能 work：** 关键在于那条看似平凡的约束——每个段恰好一个来源。它禁止两个基因组位置塌缩成一个节点（cDBG 的行为）。塌缩一旦允许，一个节点对应多个坐标，坐标映射从函数变成关系；且同一序列多次穿过同一节点时 orthology 无从定义，而没有 orthology，"变异"在图上无从定义。rGFA 用一个存储代价（重复序列被重复存储）买来坐标与 orthology 的良定义。vg 的 path 模型更一般——节点可以对应多位置、路径上可以多次出现同一节点——但作者直说：参考图不该是塌缩图，因为塌缩图的坐标翻译和变异定义都变成解谜。这是模型层的立场宣言，不是实现细节。另外两条限制（边不重叠、无多重边）纯粹是实现的化简，论文自己说理论上不必要。

**Technical advantage：** 与 cDBG 比：坐标存在且平凡。与 vg path 模型比：坐标转换从"沿路径解谜"变成"读 tag"。代价：不能表示塌缩图；片段重复区按位置各存一份。作者认为这是划算的交换——本文后半段所有下游分析（变异注释、blacklist）都只用了稳定坐标运算，没有做任何"沿路径推坐标"的事，这就是模型简化带来的红利。

**GAF（Graphical Alignment Format）：** 12 列，前 5 列和 PAF 相同（查询名、长度、起止、方向），第 6 列是图上路径，语法允许两种写法：段坐标（>s1<s2）或稳定坐标（>chr1:0-8>foo:8-16）；同一稳定序列的相邻区间可合并；若路径整体就是一条参考序列的正向路径，整列缩写成序列名——此时 GAF 退化为 PAF。第 7-12 列：路径长度、路径起止、匹配碱基数、含 gap 的比对长度、MAPQ（255 表示缺失）、加上 cg tag（图上坐标系的 CIGAR）保存碱基级比对。minigraph 同时输出两种坐标的 GAF；GraphAligner 只输出段坐标（可转换）。

**走一遍 Fig. 1 的例子（数据是论文构造的，示意）：** 图由六个段组成，S1..S3 来自 chr1（0-5、5-8、8-12），S5、S6 来自序列 foo（8-16 的一部分），S4 是另一条插入（图 1a 里 d 那支）。read2 = "CGTTTCC"（7bp）从 S2 走到插入支：GAF 第 6 列写作 ">chr1:5-8>foo:8-16"，第 7 列路径长度 = 3+8 = 11，第 10-11 列 7M。注意 "chr1:5-8" 与 "foo:8-16" 不能合并——SN 不同，这正是稳定坐标的表达力：它告诉你这 7 个碱基横跨了参考序列与一条插入序列的边界。read1 = "GTGGCT"（6bp）只走参考，路径整列写成 "chr1"，GAF 行和 PAF 行同构——这对下游的兼容性价值很大：已有 PAF 解析器几乎可以直接读"纯参考路径"的 GAF。

### 3.3 Module 2 — minigraph 序列到图比对器

**Motivation：** 构造循环需要反复把染色体长度的组装比对进图；当时没有任何工具能做到（vg 跑不通，GraphAligner 慢且错位点多）。而 minigraph 自己造图的另一个好处是：**图的内容是它自己设计的**——只含 ≥100bp 的分歧，所以"碱基水平相似的区域都在骨干上、路径不同的地方分歧大到锚点链就能分辨"，碱基比对可以整个省掉。这是 §0.3 第三步的"互相咬合"：比对器不做碱基比对不是偷懒，而是图的几何结构保证了它不需要。

#### 3.3.1 种子与线性 chaining

**做法（Fig. 2a 第一、二层）：**
1. **种子：** 对图上每个段采 minimizer（窗口 w=19，即每 19 个连续 19-mer 取哈希最小的一个），查询序列同样采 minimizer；哈希表匹配出的（段位置 x，查询位置 y）对就是**锚点**（anchor），记为三元组 (x, y, w)——锚点覆盖段上区间 [x−w+1, x]、查询上区间 [y−w+1, y]。注意 minimizer 按段采、不跨段（§5 的伏笔）。
2. **线性 chaining：** 对**同一个段**上的锚点按 x 排序，做 minimap2 式 DP。这是整篇论文公式最密的地方，拆开看：

$$f(i) = \max\Big\{\max_{j<i}\big\{f(j) + \alpha(j,i) - \beta(j,i)\big\},\; w_i\Big\}\tag{1}$$

- $f(i)$：以第 i 个锚点结尾的最优链分数，单位是"匹配碱基数"。
- $\alpha(j,i) = \min\{\min\{y_i-y_j, x_i-x_j\}, w_i\}$：锚点 i 相对前驱 j 新增的匹配碱基数——两个坐标的推进量取小（共线部分的长度），再被锚点自身宽度 $w_i$ 封顶。封顶的含义：一个锚点最多贡献它自己那么长的匹配。
- 大括号外的 $w_i$：从锚点 i 单独起一条新链。DP 的意义：每个锚点要么续在某条旧链后面，要么自立门户，取最优。
- $\beta(j,i)$：gap 罚分，控制"两个锚点之间隔了多大空隙还值得连"：

$$\beta(j,i) = \begin{cases} \infty & g_{ji} > G \\ c_1 g_{ji} + c_2 d_{ji} + \log_2 g_{ji} & 0 < g_{ji} \le G \\ 0 & g_{ji} = 0 \end{cases}$$

其中 $g_{ji} = |(y_i-y_j)-(x_i-x_j)|$ 是两侧空隙长度之差（纯 INDEL 的证据量），$d_{ji} = \min\{y_i-y_j, x_i-x_j\}$ 是较短的那一侧。参数：$G=100000$，$c_1 = e^{-dw}$，$c_2 = 0.05\,e^{-dw}$，$d=0.01$（期望每碱基分歧率），$w=19$——代入得 $c_1 \approx 0.827$，$c_2 \approx 0.041$。对比 minimap2 的取值（论文给出的等价形式）：$G=5000$，$c_1=0.19$，$c_2=0$。

逐项讲这个 gap 罚分。$g_{ji}$ 是两侧间距的**差**：查询多走 10kb 而图只走 40bp，$g \approx 10\text{kb}$——线性项 $c_1 g$ 就是"这段空隙的价格"，随插入长度线性增长。$c_2 d$ 给"即使没有长度差、两个锚点也离得远"的情况一点罚分（长距离上对角线的漂移风险）。$\log_2 g$ 是对数项，让超大空隙的边际成本递减。$g=0$ 时免费——两个锚点完美共线，随便多远都可以连，这是对"中间只是没采到 minimizer"的宽容。$g>G$ 时禁止连接——$G=100\text{kb}$ 就是 minigraph 宣称的 SV 上限 100kb 的来源：比这更长的插入会把两侧锚点彻底断开。

**$e^{-dw}$ 是理解这个函数的钥匙（论文没说，是我的推导）。** 每条链的分数单位是"匹配碱基数"。两个锚点之间隔了 g 个碱基的空隙，在期望分歧率 d 下，这段空隙里"本应有" $e^{-dw}$ 比例的位置能出 minimizer 匹配——因为一个 19-mer 在逐碱基独立突变率 d 下完全匹配的概率约是 $e^{-dw}$。所以 $c_1 g$ 读作"这段空隙里缺失的期望匹配数"，和锚点贡献的 $\alpha$ 同一单位。罚分不是拍脑袋的常数，是把"空隙"换算成"丢了多少锚点"。

**为什么 minimap2 的参数在这里会坏事，是本模块的真正动机。** 看一个具体场景（示意数值）：查询在某处插入 10kb 新序列，两侧各有一个锚点，图上间距 $x_i-x_j = 40$，查询上间距 $y_i-y_j = 10040$。则 $g = 10000$，$d_{ji} = 40$。minigraph 的罚分 $= 0.827\times10000 + 0.041\times40 + 13.3 \approx 8285$；而 minimap2 的 $G=5000 < g$，罚分 $=\infty$——**直接断链**。断链的后果对构造是致命的：两侧锚点分属两条链，中间的空隙永远进不了分歧区检测（§3.4 只扫链内相邻锚点对），这个 10kb 插入就无声无息地丢了。所以 $G=100\text{kb}$ 不是为了比对读数，是为了**保住插入两侧的锚点对**。

但允许连不代表一定连：DP 是取最大，跨空隙的价格 8285 必须由链的累计分数支付。若空隙前链已累计 30kb 的高密度锚点（链分约等于锚点密度 × 链长：示意 η=0.9 时 $f \approx 27{,}000$ 分），跨过去总分 $27{,}000 + 19 - 8285$，远大于在第二侧锚点重启（+19）——链跨过去了，两侧锚点成为链内相邻对，插入可检测。若前链太短，链就地断开，插入被错过。**所以 minigraph 对长插入的检出率依赖于两侧有足够长的、锚点密集的侧翼序列**——这是"忽略 <100kb 比对里的 SV"那条规定背后的机制（推断：论文只给了规定，没给这个机制；短比对即使跨过空隙，累计分也不够支付罚分，链必断）。

#### 3.3.2 混合 RMQ 加速

**Motivation：** Eq. 1 的朴素实现是 O(n²)——n 是锚点数，一条染色体对一条染色体的锚点动辄百万级，平方复杂度不可用。minimap2 靠启发式近邻剪枝逼近 Eq. 1，对小 gap 的 read 比对够用；但 minigraph 允许 100kb 的空隙，搜索窗口大了两个数量级，minimap2 式剪枝在长片段重复区会错过最优前驱，产生假分歧区（假变异）。需要一个"大窗口内也可靠"的加速。

**做法：** 观察一个数学事实——**若 gap cost 是线性的**，$\beta'(j,i) = c_1[(y_i-y_j)+(x_i-x_j)]$，则 Eq. 1 的最优前驱选择变得与 i 解耦：

$$f'(j) + w_j - \beta'(j,i) = \underbrace{f'(j) + w_j + c_1(y_j+x_j)}_{h'(j)} - c_1(x_i+y_i)$$

选最优前驱 j 等价于在一组候选里最大化 $h'(j)$——$h'(j)$ 只依赖 j，不依赖 i。于是问题变成一维 Range-Min-Query：维护一棵以 $y_j$ 为键、以 $-h'(j)$ 为值的二叉搜索树（论文用带子树最小值指针的 AVL 树，Fig. 5），对每个 i 查询 $\mathrm{RMQ}(y_i-G,\; y_i-w_i)$ 就得到窗口内 $-h'$ 最小的候选（即 $h'$ 最大）。查询在树上找区间两端节点、走两者之间的路径取最小值，O(m log m)，m 为树中节点数；树支持插入删除（滑窗随 x 前进）。复杂度 O(n log n)。

![Fig. 5 动态 RMQ 的 AVL 树实现](images/c0134ab5b867bba50c8aeb67df644f4d49007689536cf807779c213172f78f83.jpg)
▲ Fig. 5（论文原图）：以第一分量建二叉搜索树，每个节点带一个指针指向其子树中第二分量最小的节点；查询区间 [20,50] 时找到端点节点 (21,32) 与 (45,21)、只沿两节点间的路径取最小，无需下探子树。

**实践中怎么用（论文的混合策略）：** 到锚点 i 时，在 $G'=10000$ 的小窗口内用精确的 $\beta$ 做穷举搜索得前驱 $j_*$；同时用 RMQ 在线性 $\beta'$ 下得大窗口候选 $j'_*$。**只有当 RMQ 候选的精确得分严格更高时才采纳它**。一句话概括论文自己的话："thorough search in a small window and approximate search in a large window"——10kb 内精确、10-100kb 用近似兜底，近似解要超过精确解才上位。这解释了为什么这套机制"偶尔"才被触发（长片段重复区），以及为什么它不需要单独验证精确性——最坏情况退回小窗口精确搜索。

#### 3.3.3 图 chaining

**Motivation：** 线性 chaining 按段做、完全无视拓扑。一条查询穿过一个 10kb 插入时，插入序列在图上是一个独立的段，查询在插入段上的锚点自成一链。线性链的集合里躺着"参考左段链 → 插入段链 → 参考右段链"三段，必须按图拓扑接起来才能得到完整定位。

**做法（Fig. 2a 第三层）：** 定义线性链之间的偏序：$L_i \prec L_j$ 当且仅当 (1) $L_i$ 在查询上的结束坐标小于 $L_j$ 的结束坐标，且 (2) 图上存在从 $L_i$ 到 $L_j$ 的游走（walk）。若有多条游走，枚举最短的 16 条，选**长度最接近查询上两链间距**的那条。然后对按查询坐标排序的线性链做第二轮 DP：

$$g(i) = \max\Big\{\max_{L_j \prec L_i}\big\{g(j) + \omega(L_j) - \beta(j,i)\big\},\; \omega(L_i)\Big\}$$

$\omega(L_i)$ 是线性 chaining 给出的链分数；$\beta(j,i)$ 复用线性 gap 罚分（作用在链端点坐标上）。输出是**图链**（graph chain）：一串锚点，相邻锚点要么同段且坐标递增、要么在图上相邻的两个段上。

**为什么能 work：** 关键在"长度最接近查询间距"这条选路规则。接上面的例子：查询穿过 10kb 插入，链 L1（参考左段）和 L3（参考右段）之间查询间距约 10kb。图上 L1→L3 有两条候选游走：直走参考路径（几十 bp，锚点间距量级）或绕插入段（10kb）。不比较碱基、只比较长度，10kb 那条约等于查询间距、几十 bp 那条差了 10kb——选插入路径，正确。**距离消歧代替了碱基消歧**，这就是无碱基比对还能选对路径的原因。同样的机制让第二个带同一插入的样本自动穿行已有插入段（§3.6 走查）。

**作者自己标出的两个局限（这里坦诚得少见）：** 第一，链间只比较距离、不看序列，多条长度相近的游走时可能选错——作者加了一个 17-mer 匹配的启发式，但自认"在复杂区域不可靠"。第二，只枚举 16 条最短路，复杂子图里最优游走可能不在其中。这两个局限共同指向 VNTR 多等位区（Fig. 4）：那里几十条长度接近的等位路径，纯长度消歧必然出错。论文说未来加碱基比对来补——但碱基级环图比对正是没有实现的那个东西（§0.2 第五堵墙），所以这个"future"是有条件的。

### 3.4 Module 3 — 增量图构造

**Motivation：** 把 N 条组装变成图。逐条增量、比对吸收（§0.3 第二步）。每轮的输入是一条组装对当前图的比对（primary chains），输出是增广后的图。

**做法（Fig. 2b，分四步）：**

**第一步：primary chains 与 orthogonal 区域。** 比对器给出若干 primary chains（minimap2 式：查询上互不严重重叠的最优链集合）。一个查询区域称为 **orthogonal to the reference**，当它被一条 ≥100kb 的 primary chain 覆盖，且不与另一条 ≥20kb 的 primary chain 相交。两条规则的作用不同：≥100kb 保证侧翼足够长（链的累计分数够支付跨空隙罚分，§3.3.1）；不与 ≥20kb 的第二条链相交是 **paralog 过滤器**——一个区域若能同时被两条长链覆盖，说明它匹配图的两个位置（片段重复/旁系同源），把它的序列吸收进图会造成一个序列对应两个来源，违反 rGFA 的一节点一来源。这条过滤器是 rGFA 合法性在构造算法里的落点：**模型约束决定了哪里可以建图、哪里必须跳过**。代价是片段重复区的 SV 系统性缺失（§5.2）。

**第二步：分歧区检测。** 在 orthogonal 区域内的 primary chains 上，对每对相邻锚点打分：

$$h_i = \begin{cases} -10 & d^x_i = d^y_i \le w_{i+1} \\ \eta\cdot\max\{d^x_i, d^y_i\} & \text{otherwise} \end{cases}\tag{3}$$

$d^x_i$、$d^y_i$ 是两锚点在图侧、查询侧的间距；$\eta$ 是所有 primary chains 上平均的锚点密度。这个公式论文只给了定义没给直觉，读法如下（我的重建）：锚点密集的链上，相邻锚点几乎相接（间距 ≤ 后一个锚点的宽度，$d^x = d^y$），这种对子记 −10，是"正常背景"；真正有空隙的对子记 $\eta\cdot\max\{d^x,d^y\}$——空隙长度乘以锚点密度，单位是"这个空隙里本该有、却缺失的锚点数"。一个 10kb 插入在两侧锚点间造成 10kb 的空隙，$h \approx \eta\times10\text{kb}$（$\eta$ 在人类数据上示意取 0.2-0.9 时是 $2\times10^3 \sim 9\times10^3$），比背景 −10 大两个数量级。然后对序列 $(h_i)$ 跑 **Ruzzo-Tompa 算法**（线性时间找所有最大正和区间：正分簇、负分背景，一个区间内任意前缀后缀都为正才算 maximal segment），输出候选分歧区。这里要诚实说明：打分里 −10 和 $\eta$ 的取值论文未做敏感性分析，作者明说"−10 is an insensitive parameter due to the downstream filtering"——意思是这一步只负责**召回**（别漏掉大空隙簇），允许把正常区域也提进来，**精度交给下一步的碱基比对**。这是整条流水线最工程化、最少理论的地方。

**第三步：局部碱基比对验证。** 对每个候选分歧区，把查询区间与链给出的图路径区间做局部 pairwise 比对（minimap2 的仿射 gap 比对内核）。**注意这一步为什么不是图比对**：图链已经把图路径拉直成了一条线性序列，比对退化为序列对序列——第五堵墙第三次被绕开（第一次是 rGFA 模型避免歧义、第二次是链式定位不要碱基比对）。保留条件：含 ≥100bp 的 INDEL，或存在 ≥100bp 的区域一致性 <80%。两个条件都卡在 100bp——和图"只编码 ≥100bp SV"的定位一致。

**第四步：增广。** 把保留的分歧序列加进图：参考段在分歧边界处切分（两段的 SN/SO 不变、SR=0，坐标稳定性 §3.2 兑现）；新序列做成新段，SN = 来源组装的序列名，SO = 它在组装上的偏移，SR = 1；加链接。一个插入做成"左参考段 → 新段 → 右参考段"的替代路径，一个缺失做成一条跨过参考序列的直连边（link 的 CIGAR 可以为 0M）。下一个组装对增广后的图重复全流程。

**构造的参数表（论文散在各处，汇总）：**

| 参数 | 取值 | 作用 |
| --- | --- | --- |
| SV 长度窗口 | 100bp–100kb | 图编码的变异范围 |
| 忽略的比对长度 | <100kb | 侧翼不够长的比对里的 SV 不采信 |
| paralog 过滤 | 与 ≥20kb 的第二条 primary chain 相交即跳过 | 保证 rGFA 合法性 |
| gap 上限 G / G' | 100kb / 10kb | 链可跨的最大空隙 / RMQ 精确窗口 |
| 锚点参数 | w=19, d=0.01 | minimizer 窗口与期望分歧率 |
| 分歧区打分 | −10；η·max gap | 候选区召回 |
| 保留阈值 | ≥100bp INDEL 或 ≥100bp 区一致性 <80% | 候选区精度过滤 |
| 游走枚举 | 16 条最短路 | 图链选路 |

**为什么能 work（机制层面）：** 构造的正确性来自一个闭环：比对器认为"分歧"的地方（锚点空隙簇），碱基比对再证伪一次，两条独立证据都指向同一区域才吸收。比对器的错误模式（错路径）在构造场景下天然受限——图里不同路径之间差 ≥100bp，链式定位要么选对、要么选成另一条真实等位基因路径（那也是"存在"的序列，吸收不会引入不存在的序列）。真正的风险不是错路径，而是**组装本身的错误被当成变异吸收**（§5.2）。**Technical advantage：** 对比 VCF 路线：不需要变异 calling（检测代替分类）、不需要合并（逐条吸收天然把相似事件叠到同一气泡）、表达力不被 VCF 限制（嵌套 SV 就是图里套图）。

### 3.5 Module 4 — 变异注释与 blacklist 生成

**变异注释（服务 Fig. 3 的分析）：** 对每个变异气泡取最长等位基因序列，跑 RepeatMasker 分类散在重复。RepeatMasker 不擅长长 motif 的 VNTR（常报成不纯 STR），所以 VNTR/STR 不直接用它的输出：合并 RepeatMasker + SDUST 的低复杂度区（LCR），再用自写的 etrf 找"motif 出现 ≥2 次的纯串联重复"；一个 LCR 若 ≥70% 被 VNTR 覆盖就归为 VNTR，≥70% 被 STR 覆盖归 STR，其余 Other-LCR。注意这个 70% 规则没有依据论证，是操作定义。

**blacklist 生成（服务 E5）：** 对图里每个变异：(1) 取它在 GRCh38 上的区间，两端各扩 50bp，记 $I_0$（断点邻域）；(2) 把插入到 GRCh38 的序列（各非参考等位基因）用 `minimap2 -cxasm20 -r2k` 比对回 GRCh38，过滤 MAPQ<5 的比对；(3) $I(a,b)$ = GRCh38 上被"一致性落在 [a,b] 的比对"覆盖的区间；(4) blacklist = $I_0 \cup I(0, 0.99) \setminus I(0.998, 1)$。直觉：插入序列在 GRCh38 里有 90-99% 相似的拷贝时，携带该插入的 read 会带着错误比对到那个拷贝上、产出假变异——这些拷贝区域该拉黑；若拷贝相似度 ≥99.8%，比对几乎无误，不该拉黑——所以减去 $I(0.998,1)$。黑名单是图的一个"副产品"：只用稳定坐标和序列比对算出来，不涉及任何图算法——这本身就是 rGFA 坐标系红利的展示。

### 3.6 完整走一遍：一个 10kb VNTR 插入从组装到气泡

（以下数值均为示意，构造来展示机制；锚点密度取 η≈0.5 只为算术方便。）

**场景：** 骨干是 GRCh38 的 chr1:100,000-150,000，初始图只有这一段（记为段 R，SN=chr1, SO=100000, SR=0）。样本 A 在 chr1:120,000 处有一个 10kb 插入（60bp VNTR 单元重复 167 次）；样本 B 在同一位置有同一 VNTR 的 7kb 版本；样本 C 在 chr1:130,000-131,000 有 1kb 缺失。

**第一轮，map A 到 {R}：** 种子阶段，A 的 chr1:100,000-120,000 与 R 的对应区间产出密集锚点（示意：每 20bp 一个合并锚点，η≈0.5）。120,000 之后 A 的序列是 VNTR，在图上无匹配，锚点断流 10,040bp；130,020 处锚点恢复（对应 R 的 120,020）。线性 chaining 处理这对锚点：$g = |10040 - 40| = 10000 \le G$，$\beta = 0.827\times10000 + 0.041\times40 + 13.3 \approx 8285$。前链 20kb 的累计分 ≈ η×链长 $= 0.5\times20{,}000 = 10{,}000 > 8285$，链跨过空隙（若用 minimap2 参数 G=5000，链在此处断裂，插入丢失——这就是 G 提到 100kb 的原因）。分歧区打分：这一对 $h = 0.5\times10040 = 5020$，其余相邻对是 −10；Ruzzo-Tompa 在 (h_i) 上找到以 5020 为中心的 maximal segment。局部 pairwise 比对：查询区间（10,040bp）对链给出的图路径（R 的 40bp）——拉直后是序列对序列比对——检出 10,000bp 插入，≥100bp，保留。增广：R 在 120,000 处切成 R1（chr1:100,000-120,000）、R2（chr1:120,000-150,000），均 SR=0；新段 S_A：SN=A.chr1, SO=120,000, SR=1，序列 = VNTR×167；链接 R1⁺→S_A⁺、S_A⁺→R2⁺、R1⁺→R2⁺（参考路径 0bp——纯插入，切分点两侧直接相连）。图现在是双等位气泡：0bp vs 10kb。

**第二轮，map B 到 {R1, R2, S_A}：** B 的插入（7kb）与 S_A（10kb）同源，锚点落在 S_A 上成一条链 L2；R1 上成链 L1，R2 上成链 L3。图 chaining：L1≺L2（边存在）、L1≺L3（走 R1→R2 参考边）、L2≺L3。L1 尾到 L3 头的查询间距 ≈ 7kb；候选游走长度：R1→R2 直连 ≈0bp，绕 S_A ≈10,000bp。**长度消歧**：10,000 更接近 7,040，选绕行路径——没看一个碱基，路径选对。分歧区打分：L2 内部 B 与 S_A 之间有 3kb 的净缺失，锚点空隙簇被 Ruzzo-Tompa 提出；局部比对 B 的插入区间对 S_A 的 10kb 检出 3kb 差异；增广：S_A 切分，中间接入新段 S_B（SN=B.chr1, SO=120,000, SR=1），B 与 A 共享的 VNTR 部分走共同段、差异部分走 S_B。图变三等位：0bp / 7kb / 10kb。**这就是 Fig. 4 里多等位 VNTR 气泡的生成机制**——每个新等位基因只增加"与已有等位基因不同的部分"，相似的重复单元共享段，图保持紧凑。

**第三轮，map C 到增广图：** C 在 130,000-131,000 的缺失表现为锚点对：图侧间距 $d^x = 1020$（R2 上），查询侧 $d^y = 20$，$g = 1000$，$\beta \approx 838$，链跨过；$h = 0.5\times1020 = 510$，RT 提出候选；局部比对：查询 20bp 对图路径 1,020bp，检出 1,000bp 缺失；增广：R2 切分，加一条直连边（CIGAR 0M）构成"参考路径 1,020bp vs 缺失路径 0bp"的 bubble。**缺失在图上就是一条跳过参考序列的边**，不是负序列。

**GAF 输出（展示稳定坐标的表达力）：** A 的一条 read 跨插入时路径写作 `>chr1:100,000-120,000>A.chr1:120,000-130,000>chr1:120,000-150,000`——中间段用来源组装的坐标；C 的 read 跨缺失写作 `>chr1:100,000-130,000>chr1:131,000-150,000`——两段坐标不连续，恰好把缺失"显示"在路径里。整个例子中，没有任何一步需要碱基级图比对：跨空隙靠链，选路径靠长度，验证分歧靠拉直后的 pairwise 比对。

## 4. Experiments

### 4.1 实验协议

- **数据：** 人类图 = GRCh38 + 20 个人类单倍型（Table 3 中 17 个人类组装：14 条单倍型组装 + NA12878/NA24385/PGP1 三条 phased 组装各 2 个单倍型；推断，论文正文说 20 个单倍型，Table 3 恰好如此对上）。大猿图 = GRCh38 + 黑猩猩 Clint + 大猩猩 Susie、Kamilah + 猩猩 Susie。
- **硬件：** 人类图构造 24 CPU 线程、2.7 wall-clock 小时、98.1GB 峰值内存。
- **比对基准：** PBSIM 模拟 PacBio reads，68,857 条，N50 15kb，从 GRCh38 模拟、比对到人类图；8 线程；对手 GraphAligner v1.0.10、vg v1.21.0。
- **SV 一致判据：** 两个 callset 之间，一个 call 若在另一 callset 的 1000bp 邻域内无任何 call，算 missed。
- **工具版本：** dipcall（作者自维护版）、GATK v4.1.2、minimap2（短读比对）、RepeatMasker v1.332、SDUST、etrf。

### 4.2 Comparison experiments

#### E1 — 序列到图比对基准（minigraph vs GraphAligner vs vg）

- 检验主张：无碱基比对的链式定位，在速度、内存、位点准确率上不输有碱基比对的 GraphAligner；vg 不可用。
- 设置与对照：同一张人类图、同一批 reads、8 线程。两工具都忽略稳定坐标、所有段一视同仁——所以从 GRCh38 模拟的 reads 同时也检验了对复杂 SV 图的导航能力。
- 关键结果：minigraph 索引 100s / 比对 79s / 峰值 19.5GB / 0.5% unmapped / 1.7% wrong；GraphAligner 589s / 140s / 27.2GB / 0% / 4.6%；vg 建索引 14.7h、比对 1.8h、输出 0 条比对。GraphAligner 的 9,862 条 reads 跨 ≥2 个段（真实使用了图拓扑）。
- 定性现象：错误模式截然不同——minigraph 的错比对多数是"位点对、路径错"，GraphAligner 多数是"位点错"。作者的解释：链式定位擅长找大致位置，碱基比对擅长分辨相似路径；两者结合是理想形态（"We do plan to implement base-level alignment in minigraph in future"）。
- 能支持的结论：minigraph 快（比对 1.8×、索引 5.9×）、省内存（1.4×）、位点错误率更低（1.7% vs 4.6%），且比 GraphAligner 更能找到正确位点。
- 不能支持 / 混杂因素：**论文未给出"wrong"的判定标准**（离正确位点多远算错？正文没有）；reads 全部从 GRCh38 模拟——所有真值位点都在参考路径上，**非参考等位基因路径的导航精度完全没有被测试**，而那是 VNTR 多等位区（Fig. 4）最可能出错的地方；0.5% unmapped 未计入错误（计入后 minigraph 综合失误约 2.2%，仍优于 4.6%）；"minigraph 更准"在无碱基比对的前提下成立，是因为错位点比错路径更致命——这是对错误的非对称加权，读者应注意这个立场。

#### E2 — SV 集合的 sanity check（vs dipcall）

- 检验主张：minigraph 构造出的 SV 集合与一个成熟的基于组装的 caller 一致。
- 设置与对照：合成二倍体（CHM1+CHM13），dipcall 与 minigraph 各出一个 ≥100bp SV callset；1000bp 邻域判等。
- 关键结果：dipcall 的 14,792 个 SV 中 2.7% 被 minigraph 漏掉；minigraph 的 14,932 个中 6.0% 被 dipcall 漏掉。人工检查（IGV，"tens of differences"）发现两类原因：双方把 >100bp 的 INDEL 拆成不同的小 INDEL（一方的 miss 附近常有多个小 SV）；dipcall 跳过 SNP 高密度区或长插入+长缺失复合区，而 minigraph 在链上连接这些事件、报得更多。
- 能支持的结论：两个独立流程的 SV 集高度重叠（互盲率个位数百分比），minigraph 的构造没有系统性地假报或漏报——在**两工具共享输入组装**的前提下。
- 不能支持 / 混杂因素：没有第三方真值；两工具吃同一批组装，组装错误会以相关方式污染两者（互盲率高不能排除共同盲区）；"minigraph 报得更多"里有多少是真事件、多少是组装错误被吸收，无法区分（论文自己在 Fig. 4 讨论里承认这个问题）。

#### E3 — 人类泛基因组图构造与表征

- 检验主张：构造可扩展（时间/内存），图编码真实生物学变异。
- 设置与对照：GRCh38 + 20 单倍型；无对照工具（没有任何其他工具跑得动这个规模——vg 在 E1 已退场）。
- 关键结果：2.7h / 98.1GB / 24 线程；图 = 148,618 段、214,995 链接、37,332 个变异（变异 = 最小单源单汇子图，源汇两端都在 GRCh38 上；一条路径一个等位基因）。生物学表征：变异富集 Alu 与 VNTR；VNTR 变异中超过一半是多等位的；85 个加工假基因；VNTR 密度向端粒升高（用 GRCh38 的小卫星密度归一后仍可见但减弱）；无重复的变异同样向端粒富集——端粒下区域本来就爱出 SV。

#### E5 — blacklist：SV 区域对短读 SNP calling 的污染

- 检验主张：SV 区域是短读变异检出的系统性错误源；图能把它定位出来。
- 设置与对照：人类图**排除 CHM1/CHM13** 重建（防基准泄漏，这个 hygiene 做得干净）；blacklist 按 §3.5 生成，共 29.2Mb；SynDip 短读数据用 minimap2 比对 + GATK v4.1.2 检 SNP；两个对照：blacklist 与 SynDip confident 区域的交集只占 0.7%；真 SNP 落在 blacklist 的比例 0.7%（不富集）。
- 关键结果：GATK callset 含 32,879 个假阳性 SNP，**21% 落在 blacklist 里**——<1% 的基因组区域承载了五分之一的假阳性，约 30 倍富集（21%/0.7%）。
- 能支持的结论：短读 SNP calling 的假阳性高度集中在 SV 邻域；机制是"涉及 SV 的错配"（作者措辞），由插入序列的次级比对（§3.5 的 I(0,0.99) 设计）可解释。
- 不能支持 / 混杂因素：无 ENCODE blacklist 对照——若 ENCODE blacklist（基于 mappability/artifact）也覆盖大部分同类假阳性，则"SV 造成"的归因需要打折（两者可能高度重叠）；GATK + minimap2 不是标准配对（常规是 BWA-MEM + GATK），非标流水线对假阳性率的影响未评估；truth SNP 的绝对数小，0.7% 的对照统计功效有限。

## 5. Limitation

### 5.1 作者明确报告

1. **无碱基比对，可能被相似路径迷惑**（"may be confused by similar paths"）——并给了 E1 的错路径证据。补救计划是把碱基比对加进 minigraph，但自陈"碱基级图比对没有完全解决"：POA/PaSGAL 只做 DAG，vg 展开环最坏指数、DAG 精确模式比 PaSGAL 慢几十倍，Antipov 的环图比对只是理论，GraphAligner 是编辑距离不支持长 INDEL，Jain 2020 的仿射 gap 算法只有理论。"This may take significant effort."
2. **无法比对编码全部小变异的图**——那种图有数百万短段，minigraph 的 minimizer 不跨段索引，短段上种子断裂，线性链起不来；"This limitation can only be resolved by completely changing the minigraph mapping algorithm." 但作者同时论证小变异图不划算（图膨胀、假比对率上升、常用任务变慢——引 Forge）。
3. **不记录样本信息**（无颜色）——计划做 colored rGFA（tag 或段/边×样本二值矩阵）。
4. "Our work is still preliminary"。

### 5.2 基于论文材料的解析推断

**代价最大的假设：orthogonal 区域之外可以忽略。** 整条流水线的三个过滤——paralog 过滤（≥2 条 ≥20kb 链即跳过）、100kb 上限（G 断链）、100kb 最小比对长度——合起来的效果是：图在**片段重复区、超大 SV、未映射区域**系统性失明。而医学上最受关注的 CNV 恰恰大量住在片段重复区（SMN1/SMN2、AMY1、17q21.31、CYP2D6 这类区域）。也就是说，minigraph 的图在最需要它的地方恰好是盲的。论文为这个假设提供的辩护只有设计层面的（rGFA 合法性、比对可靠性），没有测量层面的（盲区里到底丢了多少变异）。假设不成立的后果是核心贡献打折：图的"完整性"主张必须改写为"非重复区的完整性"。这是对论文最实质的批评，也是后来 HPRC 社区公认要补的洞。

**第二个假设：组装可信。** 构造把组装序列当事实吸收，没有任何读级验证（不查原始 reads、不看覆盖度）。Fig. 4 里两个 NA12878 组装互相矛盾就是这条假设的现场反例——至少有一个是错的，而图会把错误当变异收下。VNTR 多等位区（恰好是图最得意的新发现）同时是 misassembly 高发区，这是这篇论文最不舒服的巧合。

**最小复现实验（验证盲区假设）：** 不需要复现完整系统。取一条已知携带大 CNV 的组装（如 HG002 在 AMY1 区域，或干脆合成一条带 150kb 插入的序列），跑 minigraph 建图，检查该区域是否出现变异气泡。预测：无。再做一个批量版：拿 Audano 2019（Cell）的人类 SV 真值集，统计其中多少落在"与 ≥20kb 第二链相交"或"侧翼 <100kb"的排除区——这个比例就是盲区的定量大小。若真值 SV 有 >20% 落在排除区，则"参考图"的完整性主张需要重写。

**最强攻击（替代解释）：** 对准 E5 的归因。blacklist 的假阳性富集可能主要由 mappability/重复含量驱动，而非 SV 本身：SV 邻域本来就富集重复序列（Fig. 3a 自己展示了变异富 Alu/VNTR），而重复是短读错配的经典来源。对照实验：用 ENCODE blacklist 和纯重复注释（RepeatMasker 输出）对同一批 SynDip 假阳性算同样的富集率。若 ENCODE blacklist 也覆盖大部分同类假阳性，则"SV 区域造成假阳性"的因果链条要改写为"重复区域造成假阳性，SV 恰好住在重复区域"——SV 是代理变量还是原因，当前证据分不开。另一个攻击点：E1 的 reads 全部来自 GRCh38，非参考等位基因路径从未被测试；用携带真实 SV 的 reads（从 CHM13 组装模拟）重跑，预测错路径率上升——作者在 Fig. 4 讨论里其实已经预判了这一点。

**其他值得知道的缺口：** 内存 98.1GB（20 基因组）向百基因组的外推无实验支持；无颜色意味着图不能回答"哪些样本共享哪个等位基因"，而这恰恰是分型类下游任务的前提；变异注释取最长等位基因做 RepeatMasker（最长者更可能含重复，注释有偏）；blacklist 的 29.2Mb 只覆盖 GRCh38 坐标，图外序列的对应区域无 blacklist。

## 6. 这篇论文在历史中的位置

这是一篇罕见地"定义正确"的论文——它把正确的问题（坐标系）以正确的方式（模型+格式+构造一体化设计）解决到了当时技术允许的边界。它的命运是判断它最好的证据：

- **格式赢了。** GAF 成为序列到图比对的事实标准输出格式；rGFA 的 SN/SO/SR 与"一节点一来源"被 HPRC 采纳为参考图的基础模型。GraphAligner 后来也输出 GAF（论文里已提）。
- **方法被补全而不是被推翻。** minigraph-CACTUS（Hickey et al., Nat Biotechnol 2023）把 Cactus 的碱基比对嫁接到 minigraph 的构造循环上，补的正是本文自陈的最大缺口（无碱基比对、VNTR 区错路径）；HPRC 的人类泛基因组参考（Liao et al., Nature 2023）建立在 minigraph-CACTUS 图上。比对吸收式构造从"一个可行方案"变成了"the 方案"。
- **两个预判被时间检验。** 作者说"绝大多数生物医学研究者仍会留在线性参考上，泛基因组图是线性参考的补充而不是替代"——2020-2025 的实际情况基本如此，图的价值主要兑现为 blacklist/decoy/投影这类"补丁式"用法。作者说小变异图不划算——后来 vg/GraphAligner 的实践（全变异图比对假阳性上升、速度下降）支持了这个判断。
- **一个盲区被后来的工作证实为真问题。** 片段重复区的 SV 在后续文献里被反复强调为人类泛基因组多样性的主要来源之一（HPRC 系列论文），本文的 paralog 过滤正正地挖掉了这块。后来的完整参考图用碱基比对 + 更精细的重复处理把这部分补了回来——补的方式是加复杂度，代价方向与本文的取舍完全一致。

放在更大的问题里看：这篇论文示范了一种处理"未解决问题"的策略——**不硬啃问题，而是重新定义问题直到它可解，同时保证新定义的问题仍然覆盖原问题的核心价值**。图比对无解，就把图设计成不需要图比对的样子；VCF 表达力不足，就绕开变异 calling 从比对直接建图；重复区搞不定，就诚实地画一条边界说"这里不建"。每一步"退缩"都换来了流水线的整体可行，而整体可行才让这个领域真正启动。这是系统工程里最被低估的能力，也是这篇论文最值得带走的东西。
